# Skill 研究與比較

把「想完成的工作」轉成有證據的技能選擇。可搜尋新候選，也可只評估使用者指定的項目。

## 對齊需求與現有能力

- 從對話確認工作、預期成果、使用的代理／工具與重要限制；只有缺少會影響選擇的資訊時才詢問。優先檢查現有技能與工具是否已能完成，不為使用技能而增加依賴。
- 區分可安裝的單一技能、技能集合、資源目錄與外部記憶／服務系統。目錄只是找候選的入口；完整產品的整合不能簡化成複製一份 `SKILL.md`。
- 搜尋時使用抽象的任務、能力與環境描述，不把私人會議、文件原文或憑證放入對外查詢。

## 找到可比較的候選

- 使用可用的 GitHub 連接器或網頁工具，依任務、同義表述與領域術語搜尋。已有足夠合適的候選就停止擴搜，不為湊數加入無關項目；一般可比較 3～5 個，指定單一項目時不自行擴大範圍。
- 以作者儲存庫、實際技能目錄與官方文件為判斷依據；社群推薦與星數協助發現來源，不能代替相容性、品質或安全證據。
- 記錄檢查日期、來源連結與可取得的分支／commit。核對使用者指定版本，未指定時說明本次讀到的版本，避免把持續變動的內容當成固定保證。

## 檢查會改變選擇的資訊

依候選的功能與使用者情境讀取必要資料；純指令型技能不需要套用服務部署的完整檢查。

| 面向 | 需要釐清的事 |
| --- | --- |
| 任務與環境適配 | 是否產生需要的成果；支援哪個代理與介面；是否綁定特定平台、版本或工具 |
| 維護與使用證據 | 近期與相關功能有關的更新、說明與範例、問題是否獲得回應；穩定且少更新不直接判為失效 |
| 相依與實際入口 | 讀取 `SKILL.md`，追查其中呼叫的其他技能、必要腳本、hooks、MCP、API 或命令；只讀 README 不宣稱已檢查完整行為 |
| 資料與副作用 | 會讀取、保存或修改什麼；會把哪些資料送往哪些服務；需要的權限、付費服務或背景執行；與既有設定是否衝突 |
| 採用與分享條件 | 安裝範圍與移除方式是否清楚；涉及複製、改編或再散布時，另核對授權與署名 |

查閱支援檔案時只讀取內容，不執行候選的安裝器、腳本或範例來「確認安全」。不清楚的相依、端點或資料用途標為「未確認」，並指出尚缺哪份文件或檔案。

把證據分開表達：**作者宣稱、文件記載、靜態檔案觀察、實際測試結果**。未測試不寫成已驗證；局部檢查不能保證整個專案安全，也不因未知就推定惡意。

## 提出可採用的結論

- 用精簡表格比較「候選與來源、適合情境、維護證據、相依與資料流、主要取捨」；單一候選可直接說明適用條件與缺口。較長的資料流資訊放到對應候選下方，避免過寬表格。
- 依使用者的需求推薦最合適的一項，說明勝出的理由、重要限制，以及仍待確認的事項。證據不足時可暫不推薦；沿用現有工具或不增加技能也是合理結論。不靠未定義的分數製造精確排名。
- 區分「值得進一步研究」「可考慮採用」「已安裝／已測試」。只有找到或比較的要求時，交付結論即完成，不自行下載安裝、執行技能或修改設定。
- 若使用者本次已明確要求安裝指定項目，沿用既有授權接續適用的安裝流程，不重複索取已提供的確認；安裝位置、相依與權限仍以本次範圍為準。
