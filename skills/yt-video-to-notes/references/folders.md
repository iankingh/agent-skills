# 資料夾與 Markdown 影片筆記

一般資料夾為預設目的地。先採用本次指定或對話已確認的根目錄，讀適用的 `AGENTS.md` 與既有結構；缺少目的地才詢問。只要求對話摘要時不建立檔案。Obsidian 使用 [專用規則](obsidian.md)。

## 預設結構

使用者提供一般根目錄、沒有其他慣例時，建立以下結構；明確指定的影片筆記目錄直接使用，不重複新增 `影片筆記/`。

```text
〈目標資料夾〉/
└── 影片筆記/
    ├── 講者-單支影片主題｜重點（筆記）.md
    └── 課程名稱/
        ├── README.md
        └── 章節/
            ├── 01-課程簡稱｜章節主題（筆記）.md
            └── 02-課程簡稱｜章節主題（筆記）.md
```

課程總覽的 `README.md` 正文保留完整課程標題；章節含回到總覽的連結。單支影片預設一篇，不強制建立全域索引；明確要求播放清單才建立該清單的資料夾、總覽與章節。已有課程或影片目錄時沿用，不攤平或搬移其他內容。

## 檔名、來源與查重

- 使用 [筆記標題規則](note-structure.md#標題與圖示)，保留完整正文標題。檔名遇到 `/`、`\`、控制字元或目標檔案系統不支援的字元時做必要替換；避免把標題當作路徑。不得因截斷檔名而丟失正文標題。
- 寫入前以影片 ID 搜尋目標目錄內的 Markdown，標題僅輔助。相同來源才比較是否更新，保留使用者註記及原建立日期；已不存在的舊筆記可重建。
- 不同影片即使標題相同也不覆蓋，必要時檔名加影片 ID。已存在且來源不明的檔案先比對，不直接取代。同影片的不同原文稿也不自動合併。
- 正文可用「來源紀錄」表保存：原始標題、頻道／講者、影片網址與 ID、發布日期（未取得就明記）、整理日期、影片長度、來源方法、已取得／未取得區間及原因。可沿用既有 frontmatter，不為一般資料夾強制增加特定軟體的欄位。
- 原文匯入保留正文與來源，依使用者要求決定檔名與必要連結轉換；逐位元保留時只複製／改名並比對 SHA-256，不執行渲染或繁簡轉換。

## 連結與過程檔

一般資料夾使用相對 Markdown 連結，包含 `.md` 副檔名，例如 `[回到總覽](../README.md)`。空白、`#`、括號等路徑字元以 URL 編碼處理；相對基準是目前筆記所在目錄。不要使用 Notion mention、`edit_reference` 或預設 `[[wiki links]]`。交付訊息使用實際檔案的絕對路徑 Markdown 連結。

`build.py render` 預設產生 Markdown 連結；`--notes-root` 指向實際筆記樹，`--output` 決定相對基準。只有明確使用 Obsidian 時選 `--link-style obsidian` 與對應 Vault，詳見 [工具說明](tools.md)。

字幕、音訊、轉錄、來源映射與 `created.txt` 放在輸出筆記目錄外的本批工作區，不混入正式筆記。未完成續作前保留必要素材與進度；完成後依使用者及目標專案政策保留或清理，不自動刪除原始來源、不把私人檔案放進共用技能。
