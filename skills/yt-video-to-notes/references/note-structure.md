# 新影片筆記：結構、寫作與課程流程

只在新影片整理或使用者明確要求重整內容時讀本檔。已整理文稿的原文匯入不套用模板、繁簡轉換或下列建置流程。

## 標題與圖示

使用者已提供完整標題時原樣保留；需要產生標題時使用：

| 類型 | 標題 |
| --- | --- |
| 單篇 | `主題｜副標重點（筆記）` |
| 課程章節 | `課程簡稱 NN｜章節主題：重點、重點（筆記）` |
| 課程總頁 | `講者或機構｜課程名 N 集課程筆記` |

檔名使用 `▶️ YT-完整標題.md`，不重複加前綴。新筆記正文使用 `# 合適的 emoji 完整標題`；圖示不取代標題、不加入原文匯入稿。N 使用已確認的課程集數；僅整理部分時，在總頁明示實際涵蓋範圍。

## 單篇與章節筆記的順序

章節內文依題材決定長度，不灌水。下列區段依序呈現；來源不足時寫明限制，不為填滿模板造出觀點、時間或程式碼。

1. **一句話重點**：使用 Obsidian 藍色 `note` callout（實際顏色依主題）。

   ```markdown
   > [!note] 💡 一句話重點
   > <b>用一兩句話表達本篇最重要的結論。</b>
   ```

2. **`## 這部影片是什麼`**：第一行放 `### 來源：[影片標題](原影片網址)`，連結文字保留影片標題。接著說明想回答的問題、核心觀點、適合誰，以及業配、地區用語、時效性等實際注意事項。
   - 章節改用 `## 這個章節是什麼`，並說明涵蓋第幾集至第幾集、案例與想回答的問題。
   - 多集章節逐集列來源，不拿播放清單標題冒充單支影片標題。
3. **`### 影片架構`**：表格欄位為「時間（或集數）｜段落｜重點」。
4. **內容段落**：在段落標題或個別重點後放時間戳 `[m:ss](https://www.youtube.com/watch?v=ID&t=秒數s)`。跨集必須能辨識影片與集數。技術課保留關鍵程式碼、設定檔和比較表；自行重建的示意標為「（筆記補充）」並註明未執行或實際測試範圍。
5. **`## 總結`**：收斂主要論點及適用條件，不重複整篇正文。
6. **`## 關鍵概念`**：表格欄位為「概念｜一句話解釋」。
7. **`## 快速上手：行動清單`**：使用 `- [ ]`。技術課加入「（筆記補充）新版本差異」：區分影片版本與查核當日的相關版本，引用官方文件。Spring Boot 3、Jakarta 只是例子，不固定視為最新；查不到就標示未確認。
8. **`## 應用情境（工程師版）`**：三點均標示「（筆記補充）」，依內容寫具體建議：
   - **系統設計面試（FAANG／NVIDIA）**：可討論的題目或取捨，不宣稱是特定公司的真題；無直接關聯時簡短說明。
   - **用 Claude Code 練習**：提供可操作的練習與驗收方式，不代為執行。
   - **放進人生 RPG**：將內容改寫成任務、技能與建議經驗值；若使用者已指定人生 RPG 或目標管理系統，可連到已確認的入口。未指定時僅提供文字建議，不自行建立或更新系統，不發放 XP。
9. **`## 資源`**：原影片、影片說明欄中的相關連結、工作區既有筆記 `[[完整檔名]]`，及標示為「（筆記補充）」的延伸閱讀。多集章節寫「影片：第 a 集到第 b 集」，並保留各集可點擊連結。

## 寫作規則

- 一律繁體中文、台灣用語，例如面向對象→物件導向、事務→交易、異常→例外、數據源→資料來源、接口→介面、視頻→影片、立 flag→許下目標；依語境判斷，原始程式碼、專有名詞、引用及使用者指定標題不機械替換。
- 重點使用 `<b>…</b>`；程式碼和檔名加反引號。Obsidian 內部連結使用實際存在、可唯一定位的筆記；交付訊息用絕對路徑 Markdown 連結。
- 自己新增的觀點、練習、模板、版本差異及延伸閱讀一律標「（筆記補充）」。有疑問的名言作者或出處需加一句說明；未驗證的原稿說法不改寫成已查證。
- 業配只保留有用的方法，不收錄推薦碼、優惠碼。語音辨識錯字依上下文修正；不確定數字、術語用畫面或說明欄核對，仍無法確認時明示。
- 建立前執行 `scripts/chk.py`，逐項看疑似簡體字、台灣用語與誤報提示。峰、秘、游、台、里、群、吃、占、托、干、床常有誤報，不因出現在清單就一律改字或略過上下文。
- `chk.py` 只報告、不覆寫檔案，也不能證明文章語意正確。缺 OpenCC 時回報檢查未完成，不能把沒有執行當成通過。

## 明確要求的播放清單

1. 先確認使用者要求的集數範圍、影片 ID 與每集標題。普通單支連結帶 `list`、`index` 不代表整理全清單。明確指定的課程可依主題分組成跨集章節，記錄每章涵蓋的集數；不拼接其他未指定影片。
2. 先依 [課程分流](obsidian.md#整套課程與存放分流) 確認目的地與課程屬性，再建立總頁：課程介紹、標「（筆記補充）」的學習路線，以及 `## 章節索引`。章節尚未建立時放「章節筆記建立中，完成後補上索引」，標為待補充。
3. 長內容先寫草稿 Markdown，使用 [tools.md](tools.md) 的 `build.py` 轉換時間戳和連結。只有取得內容的章節才能撰寫；若可使用背景轉錄工具，同時處理已完成轉錄的章節並保留其範圍紀錄。
4. 每篇經內容、來源、繁中與連結檢查後，以 `build.py record` 記入本批次的 `created.txt`。這份機器紀錄放在 Vault 外的本批暫存區，使用絕對檔案路徑、集數、來源與 SHA-256，不把暫存草稿當成已完成；續作結束後，將有用的來源對照與驗收收斂為 Markdown 再清理暫存紀錄。
5. 續作先執行 `build.py check`：已完成且內容相同的章節跳過；缺集或失效紀錄逐項處理。人工重新核對已修改章節後才能再次 `record`。
6. 全部指定章節完成後，把佔位文字換成「#｜筆記連結｜集數｜主題」表格，連結用 `[[完整檔名]]`。檢查無漏集、無重複涵蓋，所有連結可定位，再更新總頁狀態。

## 交付

繁體中文回覆，先放筆記的可點擊檔案連結，再用幾點說明重點。簡短交代實際讀取的是字幕、語音辨識或其他素材，時間戳是否為粗略定位，以及未涵蓋的業配或清單外集數。只有實際存在的限制才列出，不固定套用警語。
