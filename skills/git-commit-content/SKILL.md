# Git Commit 訊息（繁體中文）

產生可直接使用、忠實反映變更的提交訊息。預設採用 [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/)；摘要、內文及 footer 說明使用繁體中文，type、技術名稱與機器可辨識的 footer token 保留英文。

## 判讀變更

- 先讀適用的 AGENTS.md、CONTRIBUTING、commitlint 設定與 commit template；必要時參考近期 `git log -10 --format=%s`。明確的專案規則優先於此技能的格式偏好，使用者本次要求優先。若專案硬性要求英文，說明衝突後依使用者選擇處理。
- 在正確的儲存庫執行 `git status --short`、`git diff --cached --stat` 與 `git diff --cached`。已有暫存內容時，以暫存差異為預設提交範圍，不混入未暫存變更。
- 沒有暫存內容時，可讀 `git diff --stat` 與 `git diff` 草擬訊息，並在程式碼區塊外說明依據未暫存變更。未追蹤檔案不會出現在 diff 中，只有屬於指定範圍時才讀取並納入草稿。
- 使用者指定 diff、檔案、commit 或比較範圍時，以該範圍為準。只有文字描述時可以依據描述撰寫，不宣稱已檢查程式碼。沒有可辨識的變更時，請使用者補充內容，不杜撰提交。
- 描述行為、目的及影響；不要只把檔名清單改寫成摘要。無證據時不宣稱修復根因、效能提升、測試通過或 issue 已解決。

## 格式與文字

標題格式：`type(scope): 摘要`；scope 可省略。不相容變更使用 `type(scope)!: 摘要` 或 `BREAKING CHANGE:` footer。

```text
type(scope): 繁體中文摘要

必要時說明變更原因、行為差異與重要限制。

Refs: #123
```

上面的 `#123` 僅為格式示例，不是預設要加入的內容。

- type 使用小寫英文；scope 優先沿用專案模組名稱，例如 `auth`、`api`、`deps`，沒有明確範圍則省略。
- 摘要以「新增、修正、移除、調整、重構」等動詞直接說明結果，避免「更新程式碼」「修 bug」等模糊文字；預設不加 emoji 或句尾句號。
- 遵循專案標題長度限制；沒有設定時以 72 字元內為寫作目標，中文不按 UTF-8 位元組計算。這是本技能偏好，並非 Conventional Commits 的硬性規範。
- 簡單變更只寫標題。需要原因、重要行為差異或遷移資訊時才加內文；標題、內文及 footer 之間留空行。不要為填滿模板加入空段落。
- issue 編號、commit SHA、共同作者等 trailer 只採用已確認的資訊。使用 `Closes: #123` 表示確實解決該 issue；僅有關聯則用 `Refs: #123`，並遵循專案平台慣例。
- 不相容變更須有 `!` 或大寫 `BREAKING CHANGE:`。預設同時使用兩者，footer 說明受影響的介面與遷移方式；無法確認是否不相容時，說明疑點而不擅自標示。

## 類型選擇

`feat`、`fix` 是規範定義的類型；其餘是常見慣例，依專案允許清單調整。以主要變更目的選擇，不依修改的副檔名分類。

| type | 適用情況 |
| --- | --- |
| `feat` | 新增應用程式或函式庫功能 |
| `fix` | 修正既有功能的錯誤 |
| `docs` | 僅修改文件或註解 |
| `style` | 僅調整排版、空白、格式，無語意或行為變更；介面外觀調整依實際目的選 `feat` 或 `fix` |
| `refactor` | 重整程式結構，沒有新增功能或修正錯誤 |
| `perf` | 以改善效能為主要目的的變更，不編造量測結果 |
| `test` | 僅新增或調整測試 |
| `build` | 建置流程、打包或依賴管理 |
| `ci` | CI/CD 工作流程與設定 |
| `chore` | 其他維護工作，不作為無法判讀內容的預設類型 |
| `revert` | 撤銷先前變更；有已確認 SHA 時在內文或 footer 註明 |

配合功能或修錯加入的測試與文件通常屬於同一提交，仍以 `feat` 或 `fix` 為主。依賴更新若直接修正錯誤或帶來功能，按目的選型，避免一律歸為維護工作。任何 type 都可能包含不相容變更。

## 拆分與輸出

- 預設提供一則最佳訊息，放在 `text` 程式碼區塊中，方便複製；使用者要求只回傳內容時，省略區塊外說明。
- 多項變更服務同一目的時，寫一則涵蓋主要結果的訊息。互不相關的變更，建議依目的拆分，列出每則訊息對應的檔案或變更範圍；未獲授權不實際改動暫存區。
- 產生或檢查訊息本身不授權 `git add`、`git commit`、`git push` 或改寫歷史。使用者已明確要求提交時，沿用其授權範圍；提交前重新確認暫存差異，避免草稿與提交內容不一致，不需重複要求確認。
- 提交被 hook 擋下時，回報實際原因；不要繞過 hook 或自行擴大變更範圍。依使用者原授權處理相關問題。

## 範例

單純新增功能：

```text
feat(search): 新增依標籤篩選文章功能
```

需要背景的錯誤修正：

```text
fix(cart): 修正移除商品後總額未重新計算的問題

移除商品時重新計算小計與折扣，避免結帳頁顯示過期金額。
```

不相容的 API 變更：

```text
feat(api)!: 將訂單列表改為游標分頁

BREAKING CHANGE: 移除 page 參數，呼叫端須改用 cursor，並以回應中的 nextCursor 取得下一頁。
```
