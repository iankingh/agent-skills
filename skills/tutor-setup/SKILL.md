# 建立 StudyVault

依使用者提供的來源與學習目標，產生能回到證據、練習提取及追蹤弱項的學習資料。先讀目的地專案指引與既有模板；有既定課程或知識庫結構時沿用，不另建平行系統。只詢問會影響來源、目的地或學習範圍的缺少資訊。

## 分流與來源範圍

- 教材、PDF、網頁及逐字稿使用文件模式；程式碼專案使用程式碼模式。自動辨識只是線索，使用者指定的目的優先。
- 只處理已指定或任務必要的來源，來源與輸出位置遵循使用者授權及環境限制。一般請求不自動掃描整台電腦或下載整套課程。
- 將來源版本、路徑／URL、實際內容範圍及閱讀缺口列入對照，不憑檔名推定章節，也不把產生筆記等同完整閱讀或學會。

## 文件模式

PDF 與長文件先讀 [文件閱讀、索引與證據](references/document-reading.md)。

1. **建立來源對照**：確認封面、目錄及分布於中後段的代表頁，建立來源 → 主題 → 頁碼／章節 → 缺口的映射。多份教材須逐份核對。
2. **選擇閱讀方式**：文字型 PDF 可先擷取保留分頁的文字；掃描、錯亂表格、公式或圖表改用可用的 OCR／原頁視覺閱讀。擷取工具不是唯一選擇，也不預設需要安裝軟體。
3. **建立章節索引**：保留摘要、關鍵字、核心概念與原文位置。跨章問題取回各章證據，區分作者關係與整理者推論；摘要不能取代原文查證。
4. **形成概念與練習**：概念保持適當粒度，保留枚舉中的每個成員、例外與前提；簡短提及不強行擴寫成教材事實。補充教材另列來源。
5. **連結與回查**：重要定義及練習答案附來源頁碼／章節，圖表看過原圖再轉寫，無法取得的資料保留缺口。

## 程式碼模式

- 從專案說明、依賴與設定辨識技術棧，再讀入口、核心模組、資料模型、呼叫路徑及既有測試。針對入門目標選範圍，不預設所有檔案都需要筆記。
- 建立模組 → 檔案／符號 → 職責／介面 → 相依的對照。以實際程式碼追查一條代表性請求或資料流，不以資料夾名稱推定架構。
- 模組筆記保留用途、關鍵檔案、公開介面、內部流程、設定及測試入口；引用專案相對路徑，避免把私人絕對路徑寫入可分享內容。
- 練習可包含追查呼叫、設定判讀、定位錯誤與修改設計；答案指回對應程式碼。只要求建立入門材料時，不自行修改、安裝或啟動專案。

## 學習輸出

依 [模板與導覽](references/templates.md) 建立適合目標的結構：主題 MOC、概念／模組筆記、練習及快速參考。沿用既有語言與標籤；無目的地規則時，筆記使用使用者的語言，標籤保持一致。

練習兼顧回憶、應用與分析，答案用可折疊區塊分開，附解釋與來源；數量依教材與目標決定。概念、練習與 MOC 相互連結，弱項連回相應筆記，不捏造使用者成績或學習完成狀態。

## 驗收

依 [品質檢查](references/quality-checklist.md) 核對實際產物。修正已發現問題後檢查受影響內容；來源不可得時記錄缺口，不用反覆重試或通用知識讓檢查表表面通過。交付筆記位置、覆蓋範圍、實際驗證及尚缺內容。
